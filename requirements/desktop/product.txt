Product name:
Sync

Product type:
Sync is a desktop AI coding workspace for Windows. It helps the user build, plan, review, edit, organize, and manage software projects with an AI assistant. The app should feel like a powerful AI development control center, not just a basic chat app.

Core idea:
The user opens Sync, chooses or creates a project, gives the AI assistant a task, and Sync turns that request into a structured workflow with visible tasks, project context, file access, optional GitHub actions, optional connectors, and controlled permissions.

The AI should not feel like a simple chatbot.
It should feel like a project operator, planner, coder, reviewer, and workspace assistant.

Main product goals:
1. Help the user build software faster.
2. Help the user manage projects with AI.
3. Let the AI inspect local files with permission.
4. Let the AI propose changes before applying them.
5. Let the user approve, reject, or ignore specific tasks.
6. Keep a complete history of sessions, actions, decisions, and file changes.
7. Support GitHub workflows such as repository creation, commits, branches, issues, and pull requests.
8. Support MCP servers and external connectors.
9. Make all AI actions transparent and reviewable.
10. Keep the user in control at all times.

TASKS PANEL

This is a major feature.

After the user gives the AI a task, Sync should create a visible task checklist at the bottom or in a dedicated task panel.

The tasks should represent the AI's working plan.

Each task row should include:
- checkbox/status indicator
- task title
- optional short explanation
- status
- priority
- related file/tool if relevant
- action buttons

Task statuses:
- Pending
- In Progress
- Completed
- Skipped
- Ignored
- Failed
- Waiting for Approval
- Blocked

Each task should support:
- mark complete
- skip task
- ignore task
- restore ignored task
- edit task
- reorder task
- expand details
- ask AI about this task
- attach task to a file
- link task to a GitHub issue
- link task to a connector result

The user should be able to draw a line through a task or mark it as ignored.
When the user crosses out or ignores a task, the AI must treat that task as excluded from the workflow.

Ignored task behavior:
- The task remains visible but visually marked as ignored.
- The AI should not execute it.
- The AI should not plan around it unless the user restores it.
- The task should appear in history as ignored.
- The user can restore it later.

Completed task behavior:
- Completed tasks show a checkmark.
- The AI should explain briefly what was completed.
- If the task changed files, it should link to the diff.
- If the task used a tool, it should link to the tool call record.

Task creation behavior:
- For every non-trivial user request, Sync should generate tasks.
- For small questions, tasks are optional.
- The AI should not create too many tasks for simple requests.
- Complex requests should be broken into clear phases.

Example task list for "Create GitHub repository for this project":
1. Check current project folder
2. Inspect Git status
3. Ask for repository name if missing
4. Create GitHub repository
5. Initialize Git if needed
6. Add remote origin
7. Create initial commit
8. Push to GitHub
9. Save repository link to project history

Example task list for "Improve this app UI":
1. Review current screens
2. Identify inconsistent layout areas
3. Propose UI improvements
4. Generate file changes
5. Show diff preview
6. Wait for approval
7. Apply approved changes
8. Save summary to history

FILE ACCESS

Sync may access local project files only after the user opens or selects a project folder.

File access rules:
- Sync should not access the entire computer automatically.
- Sync should only access folders the user explicitly opens.
- The user can add more allowed folders manually.
- The AI can read files inside allowed folders.
- The AI can search files inside allowed folders.
- The AI can propose file edits.
- The AI cannot write files unless the user approves or permissions allow it.
- The AI cannot delete files without explicit confirmation.
- The AI cannot modify sensitive files without confirmation.

Sensitive files include:
- .env

GITHUB / REPOSITORIES

Sync should support GitHub integration.

GitHub capabilities:
- connect GitHub account
- view connected user
- create repository
- connect local project to repository
- initialize Git in local folder
- view Git status
- create branch
- switch branch
- stage changes
- commit changes
- push changes
- pull changes
- create pull request
- create issue
- link tasks to issues
- link file changes to commits
- open repository in browser
- clone repository
- import repository as project

Repository creation workflow:
1. User asks Sync to create a GitHub repository.
2. Sync checks if GitHub is connected.
3. If not connected, Sync asks user to connect GitHub.
4. Sync asks for repository name if not provided.
5. Sync asks whether the repo should be public or private.
6. Sync creates repository only after user approval.
7. Sync initializes Git locally if needed.
8. Sync adds remote origin.
9. Sync creates commit if user approves.
10. Sync pushes to GitHub if user approves.
11. Sync saves repository link in project history.

GitHub safety rules:
- Never create public repositories without clear user approval.
- Never push secrets.
- Warn if .env or credential files are staged.
- Show commit summary before committing.
- Show push target before pushing.
- Ask before force push.
- Ask before deleting branches.
- Ask before making repository public.
- Ask before deleting repository.
