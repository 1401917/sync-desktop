SECURITY GOAL

Sync must be secure by default.

The AI assistant is powerful and can interact with local files, project folders, Git, GitHub, MCP servers, connectors, terminal commands, databases, and external services. Because of that, Sync needs a strong security model that keeps the user in control at all times.

Primary security goals:
1. Prevent silent file modification.
2. Prevent silent command execution.
3. Prevent secret exposure.
4. Prevent dangerous Git/GitHub actions.
5. Prevent untrusted MCP abuse.
6. Prevent connector misuse.
7. Prevent accidental data leakage.
8. Prevent malicious prompt injection from files, web pages, connectors, or MCP results.
9. Protect API keys and tokens.
10. Keep detailed audit logs.
11. Make risky actions explicit and reviewable.
12. Keep Sync local-first.
13. Make all permissions understandable and reversible.
14. Let the user inspect, approve, deny, pause, revoke, and roll back actions.
15. Keep secure defaults even if the user is using AI heavily.


SECURITY PRINCIPLES

Sync should follow these principles:

1. Least privilege:
Only give the AI the minimum access required for the current task.

2. Explicit user consent:
Sensitive actions require user approval.

3. Local-first privacy:
Local project data stays local unless the user uses an AI provider or connector that requires sending data.

4. Clear boundaries:
The AI can only access allowed folders, selected connectors, configured MCP servers, and approved tools.

5. No silent destructive actions:
No deletion, overwrite, command execution, push, public repo creation, connector write, or database mutation without permission.

6. Traceability:
Every important action must be logged.

7. Reversibility:
File changes should support snapshots and rollback when possible.

8. Secret protection:
Secrets must be detected, masked, protected, and excluded from AI context unless explicitly approved.

9. Prompt injection resistance:
External content must be treated as untrusted data, not instructions.

10. Secure defaults:
The default mode should be useful but safe.
